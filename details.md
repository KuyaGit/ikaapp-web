# ikaapp — App Details

## Overview

**ikaapp** is a personal finance management mobile app built with Expo/React Native. It helps users track income (blessings), budget allocations, savings, expenses, and tithes — designed around a Filipino payroll cycle with support for semi-monthly, monthly, bi-weekly, and weekly disbursement schedules.

Additional features: a **first-run onboarding wizard** for initial setup, a **biometric/PIN App Lock** with 30-second background auto-lock, and an **in-app update check** that prompts when a new release is available on the landing page.

- **Platform:** iOS, Android, Web (react-native-web)
- **Framework:** Expo ~54 / React Native 0.81.5 / React 19
- **Architecture:** New Architecture enabled (`newArchEnabled: true`)
- **Orientation:** Portrait only
- **Bundle ID:** `com.ikaapp`

## Screens

### AnimatedSplashScreen
**File:** `src/screens/AnimatedSplashScreen.tsx`

Custom launch animation overlay shown while the native Expo splash hides. Pulses the logo then scales/fades out.

**Props:** `onComplete: () => void`

**Animation sequence:**
- 3 pulse iterations: scale 1 → 1.25 → 1 (400 ms each).
- Exit (parallel): scale → 0.05 over 600 ms, opacity → 0 over 500 ms.
- 3 000 ms `setTimeout` fallback — guarded by `calledRef` so `onComplete` fires exactly once.
- `onLayout` calls `SplashScreen.hideAsync()` to dismiss the native splash.

**Storage:** none.

### OnboardingScreen
**File:** `src/screens/OnboardingScreen.tsx`

First-run 3-step wizard shown when no `BudgetSettings` exist in storage. Collects pay schedule and budget allocations and writes the initial settings.

**Props:** `onComplete: () => void`

**Steps:**
1. **Welcome** — app icon, name, tagline, "Get Started →" button.
2. **Pay Frequency** — 4-card grid (Monthly / Semi-monthly / Bi-weekly / Weekly), then a frequency-dependent day-config block:
   - Monthly → single `DayInput` (day of month).
   - Semi-monthly → two `DayInput`s.
   - Weekly / Bi-weekly → 7-button day-of-week row; Bi-weekly also adds a reference-date field (defaults to today).
   - Default day values seeded per frequency on selection (monthly 15, semi-monthly [10, 25], weekly/bi-weekly day 5).
3. **Budget Allocation** — fixed rows for Tithes 🙏 / Savings 💰 / Expenses 💸 (percentage inputs), plus dynamic custom-category rows (emoji picker, name, %, delete); total badge shows `{total}% / 100%` in green/red; "Finish Setup ✓" disabled unless total === 100.

**Step transitions:** fade-out / fade-in animation (150 ms delay) via `Animated.Value`.

**On finish:** writes `BudgetSettings` with `monthlyIncome: 0`, the three built-in category ids (`'1'/'2'/'3'`) plus any custom categories (with `icon`), and the chosen `disbursementSchedule`.

**Storage writes:** `STORAGE_KEYS.BUDGET_SETTINGS`.

### LockScreen
**File:** `src/screens/LockScreen.tsx`

App-lock gate shown when App Lock is enabled. Attempts biometric authentication first; falls back to a 4-digit PIN pad.

**Props:** `onUnlock: () => void`

**Biometric flow:**
1. On mount (once, guarded by `attempted` ref): check `hasHardwareAsync()` and `isEnrolledAsync()`.
2. If hardware/enrollment missing → show PIN pad; if no PIN stored → show "No PIN set" warning.
3. If available → `authenticateAsync({ promptMessage: 'Unlock ikaapp', fallbackLabel: 'Use PIN' })`.
   - Success → `onUnlock()`.
   - Failure → show PIN pad (reads stored PIN; shows "No PIN set" if absent).

**PIN pad:**
- 4 dots + 3×4 keypad (0–9 + ⌫ backspace).
- `pressDigit` caps at 4 digits; `pressUnlock` reads PIN from SecureStore and compares — mismatch clears and shows error.
- Unlock button disabled when `pin.length < 4` or `noPin`.
- "Use Face ID / Touch ID" link retries biometric authentication.

**Storage:** reads PIN from **Expo SecureStore** (`lock_pin`). No AsyncStorage usage.

### BudgetSettingsScreen
**File:** `src/screens/BudgetSettingsScreen.tsx`

Editable settings for budget allocations, pay schedule, and App Lock.

**Layout (top-to-bottom):**
- **Allocation** — category rows (emoji-picker, color swatch, name, %, delete); dashed "+ Add Category" row; `{total}% / 100%` badge.
- **Salary Disbursement** — 4-button frequency selector + frequency-dependent day config (see OnboardingScreen step 2).
- **Security** — "App Lock" label + `Switch`.
- Full-screen **PIN-setup modal** (enter → confirm phases, 4 PIN dots, numeric keypad).
- Footer (outside scroll): validation hint + Save button + "💝 Send Love" → DonateScreen.
- Animated snackbar ("✓ Settings saved").

**Guards:**
- `beforeRemove` listener intercepts back-navigation when settings are dirty; shows `UnsavedChangesModal` (Save & Leave disabled unless allocations total 100%).
- Save shows `ConfirmSaveModal` when dirty, else saves immediately.

**App Lock toggle:**
- **ON** → opens PIN-setup modal (enter + confirm; mismatch → retry with error). On success: `setSecureItem('lock_pin', pin)`, sets `LOCK_ENABLED = 'true'` and `LOCK_PIN_SET = 'true'`, fires `notifyLockEnabledChanged(true)`.
- **OFF** → confirm alert, then `deleteSecureItem('lock_pin')`, sets `LOCK_ENABLED = 'false'`, removes `LOCK_PIN_SET`, fires `notifyLockEnabledChanged(false)`.

**On save:** preserves existing `monthlyIncome`, writes `BUDGET_SETTINGS`, fires `notifySettingsChanged()`, reschedules disbursement notifications if income > 0.

**Route params:** none (inside `HomeStackParamList`).

**Data read/write:** `BUDGET_SETTINGS`, `LOCK_ENABLED`, `LOCK_PIN_SET`. **SecureStore:** `lock_pin`.

### SalaryEntryScreen
**File:** `src/screens/SalaryEntryScreen.tsx`

Log or edit the net salary received for a pay period.

**Route params:** `{ grossExpected: number; editEntry?: { id: string; netReceived: number } }`

**Data read/write:** `SALARY_ENTRIES`, `BLESSING_ENTRIES`, `LAST_DISBURSEMENT_DATE`, `BUDGET_SETTINGS`, `INCOME_CHANGE_LOG`.

## Hooks

### useLockTimeout
**File:** `src/hooks/useLockTimeout.ts`

`useLockTimeout(onLock, timeoutMs, enabled)`

Listens to `AppState`. When the app moves to background/inactive, records a timestamp. On returning to active, calls `onLock` if elapsed time exceeds `timeoutMs` (30 000 ms in `App.tsx`).

- Uses a ref for `onLock` so the callback stays current without re-subscribing.
- Only active when `enabled` is `true`. Effect deps: `[enabled, timeoutMs]`.

## Security & App Lock

| Concern | Implementation |
|---|---|
| PIN storage | Expo SecureStore (`lock_pin`); web shimmed to AsyncStorage `__secure__lock_pin` via `secureStorage.ts` |
| Lock state | AsyncStorage `lock_enabled = 'true'/'false'` + in-memory pub/sub via `lockEvents.ts` |
| PIN flag | AsyncStorage `lock_pin_set = 'true'` (deleted when lock disabled) |
| Biometric | `expo-local-authentication` — Face ID / Touch ID; falls back to PIN on failure or no enrollment |
| Auto-lock | `useLockTimeout(30_000)` in `App.tsx` — triggers after 30 s in background |
| Cross-component sync | `notifyLockEnabledChanged` in `BudgetSettingsScreen` → `onLockEnabledChanged` in `App.tsx` |

**PIN setup flow (BudgetSettingsScreen):** Toggle App Lock ON → PIN-setup modal opens (enter 4 digits → confirm 4 digits; mismatch resets to enter phase with error) → match: writes PIN to SecureStore, sets `LOCK_ENABLED='true'` and `LOCK_PIN_SET='true'`, broadcasts `notifyLockEnabledChanged(true)`.

**PIN disable flow:** confirm alert → `deleteSecureItem('lock_pin')` + `LOCK_ENABLED='false'` + remove `LOCK_PIN_SET` + broadcast.

## Updates / Version Check

**File:** `src/utils/versionCheck.ts`

At launch, `App.tsx` calls `checkForUpdate()` immediately (before onboarding/lock checks).

- Returns `null` on web (`Platform.OS === 'web'`).
- Fetches `release.json` (no-cache) from the GitHub Pages landing site: `https://kuyagit.github.io/ikaapp-web/apk/release.json`.
- Compares `json.version` (strips leading `v`) against `Constants.expoConfig?.version`.
- If versions differ (covers both newer remote and stale dev build), returns `{ remoteVersion, downloadUrl }`.
- Returns `null` on any fetch/parse error (non-critical).

`UpdateModal` is rendered at the top of `App.tsx` in all branches. When `updateInfo` is non-null the modal appears with "Download Update" (opens the APK URL) and "Later".

## Key Business Logic

### Monthly Income
- Auto-computed: `netReceived × disbursementsPerMonth(frequency)`.
- Stored in `BudgetSettings.monthlyIncome` each time salary is logged or edited.
- Dashboard "Monthly Income" card shows current month's total blessings, not the stored value.
- Starts at `0` after onboarding — set on first salary log.

### Budget Base (`base`)
```
base = periodSalary?.netReceived ?? (monthlyIncome / disbursementsPerMonth(frequency))
```
Falls back to expected gross when no salary is logged for the current period. All three tracker screens (Savings, Expenses, Category) and the Dashboard use this same derivation.

### Blessings → Tithes
- Weekly blessings = sum of `BlessingEntry.amount` for Mon–Sat of current week.
- Weekly tithes = `weeklyBlessings × tithesPercent / 100`.
- Logging salary auto-creates a "Salary Disbursement" `BlessingEntry` for the same date.
- Editing salary updates the matching `BlessingEntry` atomically.

### Pay Period
- `start` = most recent disbursement day on or before today (`getMostRecentDisbursementDate`).
- `end` = day before next payday (`getCurrentBudgetPeriod`).
- Savings and expenses on the dashboard are filtered by `{ start, end }`.

### Payday Status

| Status | Condition |
|---|---|
| `no_schedule` | No disbursement schedule configured |
| `logged` | Salary entry exists within the current period |
| `payday_today` | Today is a payday and no salary is logged yet |
| `overdue` | Last payday has passed with no salary logged |

### Notifications
- Up to 4 upcoming payday notifications scheduled at 08:00 local on each payday date.
- Previous notification IDs cancelled before rescheduling (stored in `NOTIFICATION_IDS`).
- If status is `payday_today` or `overdue` (within 3 days) → immediate one-off reminder (+5 s delay).
- Notification tap → deep-links to `SalaryEntry` screen via `navigationRef`.

## App Initialization (`App.tsx`)

```
1. SplashScreen.preventAutoHideAsync()          — keep native splash visible
2. Notifications.setNotificationHandler(...)    — banner + list + sound, no badge
3. useLockTimeout(setIsLocked, 30_000, ...)     — background auto-lock setup (hook)
4. On mount (parallel):
   a. checkForUpdate()                          — fetch release.json, sets updateInfo
   b. AsyncStorage.getItem(BUDGET_SETTINGS)     — sets needsOnboarding (null → bool)
   c. AsyncStorage.getItem(LOCK_ENABLED)        — sets lockEnabled; sets isLocked if 'true'
5. onLockEnabledChanged subscription            — keeps lockEnabled in sync with BudgetSettings
6. After splash done + onboarding complete:
   a. requestNotificationPermissions()
   b. scheduleDisbursementNotifications(...)
   c. checkAndNotifyUnloggedPayday(...)          — all wrapped in try/catch (non-critical)

Render gate order:
  loading (needsOnboarding/lockEnabled === null) → AnimatedSplashScreen
  needsOnboarding                                → OnboardingScreen (prop: onComplete)
  isLocked && lockEnabled                        → LockScreen (prop: onUnlock)
  else                                           → AppNavigator
  (UpdateModal always rendered; visible when updateInfo !== null)
```

**Dev seed:** `scripts/apply-seed.ts` (`SEED_VERSION = 'v1'`, flag `dev_seed_applied`, `__DEV__`-gated). **Not currently called at startup** — it is dead code at runtime. To seed: call `applySeed()` manually or wire it into App.tsx in development.
